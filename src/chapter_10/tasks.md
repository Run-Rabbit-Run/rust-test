# Глава 10. Обобщенные типы, трейты и время жизни: практические задания

Цель этих заданий - закрепить три темы главы 10: обобщенные типы данных, трейты для общего поведения и времена жизни ссылок.

Решения можно писать в `src/main.rs` или создать отдельный модуль, например `src/chapter_10/answers.rs`, и вызывать функции из `main`. После каждого задания запускай:

```bash
cargo run
```

Если задание просит только проверить типы или ошибку компилятора, используй:

```bash
cargo check
```

## Задание 1. Обобщенная функция поиска максимума

### Краткая теория

Обобщенный параметр типа, например `T`, позволяет написать одну функцию для разных конкретных типов. Но если функция сравнивает значения через `>`, компилятору нужно знать, что тип поддерживает сравнение. Для этого используют ограничение трейтом: `T: PartialOrd`. Если функция может не найти значение, лучше вернуть `Option<T>` или `Option<&T>`, а не вызывать панику.

### Что нужно сделать

Напиши функцию:

```rust
fn largest<T: PartialOrd>(list: &[T]) -> Option<&T>
```

Требования:

- если срез пустой, верни `None`;
- если срез не пустой, верни ссылку на наибольший элемент;
- проверь функцию на `Vec<i32>`, `Vec<char>` и `Vec<f64>`;
- отдельно проверь пустой `Vec<i32>`;
- обработай результат через `match`, без `unwrap`.

## Задание 2. Обобщенная структура с двумя типами

### Краткая теория

Структура может быть обобщенной по одному или нескольким типам. В `Point<T>` оба поля с типом `T` обязаны иметь один конкретный тип внутри одного значения. Если поля должны иметь разные типы, используют несколько параметров: `Point<T, U>`.

### Что нужно сделать

Создай структуру:

```rust
struct Point<T, U> {
    x: T,
    y: U,
}
```

Реализуй для нее методы:

- `new(x: T, y: U) -> Point<T, U>`;
- `x(&self) -> &T`;
- `y(&self) -> &U`;
- `swap(self) -> Point<U, T>`, который меняет `x` и `y` местами.

Проверь структуру на значениях:

- `Point<i32, i32>`;
- `Point<i32, f64>`;
- `Point<&str, String>`.

## Задание 3. Методы только для конкретного типа

### Краткая теория

`impl<T, U> Point<T, U>` добавляет методы для всех вариантов `Point`. Но можно написать реализацию только для конкретного типа, например `impl Point<f64, f64>`. Тогда методы из такого блока будут доступны только значениям именно этого типа.

### Что нужно сделать

Используй структуру `Point<T, U>` из предыдущего задания.

Добавь отдельный блок:

```rust
impl Point<f64, f64> {
    fn distance_from_origin(&self) -> f64 {
        // ...
    }
}
```

Требования:

- посчитай расстояние от точки до начала координат по формуле `sqrt(x * x + y * y)`;
- создай `Point::new(3.0, 4.0)` и выведи расстояние;
- создай `Point::new(3, 4)` и оставь в комментарии объяснение, почему у него нельзя вызвать `distance_from_origin`;
- рабочий код должен компилироваться.

Подсказка: для `f64` доступен метод `.sqrt()`.

## Задание 4. Обобщенное перечисление

### Краткая теория

Перечисления тоже могут хранить обобщенные типы. Стандартные `Option<T>` и `Result<T, E>` устроены именно так: конкретный тип значения становится известен при использовании перечисления.

### Что нужно сделать

Создай перечисление:

```rust
enum Slot<T> {
    Empty,
    Filled(T),
}
```

Реализуй методы:

- `is_empty(&self) -> bool`;
- `is_filled(&self) -> bool`;
- `replace(&mut self, value: T) -> Option<T>`.

Логика `replace`:

- если слот был `Empty`, положи новое значение и верни `None`;
- если слот был `Filled(old)`, замени значение и верни `Some(old)`.

Проверь `Slot<String>` и `Slot<i32>`.

## Задание 5. Собственный трейт с реализацией по умолчанию

### Краткая теория

Трейт описывает поведение, которое могут разделять разные типы. В трейте можно объявить обязательные методы и методы с реализацией по умолчанию. Тип, который реализует трейт, обязан предоставить обязательные методы, а методы по умолчанию может переопределить.

### Что нужно сделать

Создай трейт:

```rust
trait Summary {
    fn title(&self) -> &str;

    fn summarize(&self) -> String {
        format!("{}...", self.title())
    }
}
```

Создай две структуры:

- `Article { title: String, author: String, text: String }`;
- `Post { username: String, text: String }`.

Требования:

- реализуй `Summary` для `Article`, используя `summarize` по умолчанию;
- реализуй `Summary` для `Post`, переопределив `summarize`;
- создай несколько значений и выведи результат `summarize`;
- добавь комментарий, какой метод был обязательным, а какой имел реализацию по умолчанию.

## Задание 6. Параметры функций с трейтами

### Краткая теория

Если функция должна принимать любой тип с определенным поведением, можно использовать `impl Trait` или обычный обобщенный параметр с ограничением. Запись `fn notify(item: &impl Summary)` удобна для простых случаев. Запись `fn notify<T: Summary>(item: &T)` полезна, когда один и тот же тип `T` встречается в сигнатуре несколько раз.

### Что нужно сделать

Используй трейт `Summary` из предыдущего задания.

Напиши функции:

```rust
fn notify(item: &impl Summary)
fn notify_same_type<T: Summary>(first: &T, second: &T)
fn notify_any_pair<T: Summary, U: Summary>(first: &T, second: &U)
```

Требования:

- каждая функция должна вывести краткое описание через `summarize`;
- вызови `notify` для `Article` и `Post`;
- вызови `notify_same_type` для двух `Article`;
- вызови `notify_any_pair` для `Article` и `Post`;
- оставь в комментарии объяснение, почему `notify_same_type(article, post)` не подходит.

## Задание 7. Ограничения трейтов и `where`

### Краткая теория

Один тип может быть ограничен сразу несколькими трейтами: `T: Display + PartialOrd`. Когда ограничений становится много, удобнее использовать `where`, чтобы сигнатура функции или блока `impl` оставалась читаемой. Также можно делать методы доступными только тем `T`, которые удовлетворяют ограничениям.

### Что нужно сделать

Создай структуру:

```rust
struct Pair<T> {
    x: T,
    y: T,
}
```

Реализуй:

```rust
impl<T> Pair<T> {
    fn new(x: T, y: T) -> Self {
        Self { x, y }
    }
}
```

Затем добавь отдельный блок:

```rust
impl<T> Pair<T>
where
    T: std::fmt::Display + PartialOrd,
{
    fn cmp_display(&self) {
        // ...
    }
}
```

Требования:

- `cmp_display` должен вывести, какое поле больше или что значения равны;
- проверь `Pair::new(10, 20)`;
- проверь `Pair::new("beta", "alpha")`;
- создай свой тип без `Display` или без `PartialOrd` и в комментарии объясни, почему для него метод `cmp_display` недоступен.

## Задание 8. Возврат значения, реализующего трейт

### Краткая теория

`impl Trait` можно использовать в возвращаемом типе: `fn make_item() -> impl Summary`. Так вызывающий код знает, что результат поддерживает методы трейта, но не зависит от конкретного типа. При этом функция с `impl Trait` должна возвращать один конкретный тип, а не разные типы в разных ветках `if`.

### Что нужно сделать

Используй `Article`, `Post` и `Summary`.

Напиши функцию:

```rust
fn create_default_article() -> impl Summary
```

Она должна вернуть `Article` с любыми тестовыми данными.

Затем сделай эксперимент:

- временно напиши функцию, которая по `bool` пытается вернуть то `Article`, то `Post` через `-> impl Summary`;
- запусти `cargo check` и посмотри ошибку компилятора;
- убери некомпилирующийся код или оставь его закомментированным;
- в комментарии объясни, почему такой возврат не работает.

## Задание 9. Времена жизни в функциях

### Краткая теория

Аннотации времени жизни не продлевают жизнь ссылок. Они описывают связь между входными и выходными ссылками, чтобы компилятор мог проверить безопасность. Если функция возвращает одну из двух входных ссылок, нужно указать, что возвращаемая ссылка живет не дольше обеих входных.

### Что нужно сделать

Напиши функцию:

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str
```

Требования:

- верни более длинную строку;
- проверь функцию на двух строках, которые живут в одной области видимости;
- создай пример с внутренней областью видимости, где результат используется до выхода из этой области;
- оставь в комментарии пример, который не компилируется, если попытаться использовать результат после уничтожения одной из строк;
- своими словами в комментарии объясни, почему время жизни результата ограничено более короткой из входных ссылок.

## Задание 10. Структура, хранящая ссылку

### Краткая теория

Если структура хранит ссылку, в ее определении нужно явно указать время жизни этой ссылки: `struct Fragment<'a> { text: &'a str }`. Это означает, что значение структуры не может жить дольше данных, на которые оно ссылается. Для методов часто срабатывают правила элизии времен жизни, поэтому не каждую ссылку нужно размечать вручную.

### Что нужно сделать

Создай структуру:

```rust
struct TextFragment<'a> {
    text: &'a str,
}
```

Реализуй методы:

- `new(text: &'a str) -> TextFragment<'a>`;
- `len(&self) -> usize`;
- `announce_and_return(&self, announcement: &str) -> &str`.

Требования:

- создай `String` с несколькими предложениями;
- выдели первое предложение через `split('.')` или другой способ;
- создай `TextFragment`, который хранит ссылку на первое предложение;
- выведи длину фрагмента;
- вызови `announce_and_return` и выведи возвращенный текст;
- добавь переменную `let slogan: &'static str = "Rust keeps references honest";` и выведи ее;
- в комментарии объясни, почему строковый литерал может иметь время жизни `'static`.

## Задание 11. Итоговая задача: мини-журнал заметок

### Краткая теория

В реальном коде обобщенные типы, трейты и времена жизни часто используются вместе. Обобщенная структура хранит разные виды данных, трейт описывает общее поведение, а lifetime-аннотации нужны, когда функция или структура возвращает либо хранит ссылку на существующее значение.

### Что нужно сделать

Собери небольшую программу для заметок.

Создай трейт:

```rust
trait Preview {
    fn preview(&self) -> String;
}
```

Создай структуру:

```rust
struct Note<T> {
    title: String,
    content: T,
}
```

Требования:

- реализуй `Preview` для `Note<String>`;
- в `preview` верни строку вида `"title: first_part"`, где `first_part` - первые 30 символов содержимого или все содержимое, если оно короче;
- напиши функцию `choose_longer_preview<'a, T: Preview>(first: &'a T, second: &'a T) -> &'a T`, которая возвращает ссылку на заметку с более длинным `preview`;
- создай структуру `Selection<'a, T> { item: &'a T, reason: String }`;
- сохрани выбранную заметку в `Selection`;
- выведи `selection.item.preview()` и `selection.reason`;
- не используй `clone` для выбора заметки: функция должна возвращать ссылку, а не владеть заметкой.

Дополнительно: замени реализацию `Preview for Note<String>` на более универсальную реализацию для всех `Note<T>`, где `T` можно отформатировать через `std::fmt::Display`.
