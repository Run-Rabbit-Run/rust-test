# Глава 9. Обработка ошибок: практические задания

Цель этих заданий - закрепить подход Rust к ошибкам: когда программа должна остановиться через `panic!`, а когда нужно вернуть `Result<T, E>` и дать вызывающему коду решить, что делать дальше.

Решения можно писать в `src/main.rs` или создать отдельный модуль, например `src/chapter_9/answers.rs`, и вызывать функции из `main`. После каждого задания запускай:

```bash
cargo run
```

Для заданий, где нужно только проверить компиляцию, используй:

```bash
cargo check
```

## Задание 1. Безопасный доступ к элементу

### Краткая теория

Обращение к вектору через индекс, например `numbers[10]`, вызывает `panic!`, если такого элемента нет. Это неустранимая ошибка: Rust останавливает программу, потому что продолжение работы могло бы быть небезопасным. Если отсутствие элемента является нормальной ситуацией, лучше использовать метод `get`, который возвращает `Option<&T>`.

### Что нужно сделать

Создай функцию:

```rust
fn print_number_at(numbers: &[i32], index: usize)
```

Она должна:

- пытаться получить элемент через `numbers.get(index)`;
- если элемент есть, вывести его значение;
- если элемента нет, вывести понятное сообщение без паники;
- отдельно временно проверь, что `numbers[index]` с неверным индексом приводит к панике, затем убери этот код.

Проверь функцию на индексах `0`, `2` и `99`.

## Задание 2. Намеренная паника для нарушения правила

### Краткая теория

`panic!` стоит использовать, когда программа оказалась в состоянии, которое не должно быть возможным при корректном использовании кода. Например, если функция принимает процент скидки, а по правилу предметной области скидка не может быть больше `100`, это нарушение контракта функции.

### Что нужно сделать

Напиши функцию:

```rust
fn calculate_discount_price(price: u32, discount_percent: u32) -> u32
```

Требования:

- если `discount_percent > 100`, вызови `panic!` с понятным сообщением;
- иначе верни цену после скидки;
- проверь функцию на скидках `0`, `25`, `100`;
- временно вызови функцию со скидкой `150`, посмотри сообщение паники, затем закомментируй этот вызов.

Дополнительно: в комментарии к функции объясни, почему здесь выбран `panic!`, а не `Result`.

## Задание 3. Разбор числа через Result

### Краткая теория

`Result<T, E>` описывает операцию, которая может завершиться успешно или ошибкой. Вариант `Ok(value)` содержит успешное значение, а `Err(error)` содержит ошибку. Для обработки обоих вариантов удобно использовать `match`.

### Что нужно сделать

Напиши функцию:

```rust
fn parse_age(text: &str) -> Result<u8, std::num::ParseIntError>
```

Она должна преобразовать строку в `u8` через `parse`.

В `main` вызови функцию для значений:

- `"25"`;
- `"abc"`;
- `"300"`.

Для каждого результата через `match` выведи:

- возраст, если получился `Ok`;
- текст ошибки, если получился `Err`.

Обрати внимание: `"300"` не помещается в `u8`, поэтому это тоже ошибка разбора.

## Задание 4. Открытие файла с match

### Краткая теория

Многие операции ввода-вывода возвращают `Result`. Например, `File::open` возвращает `Result<File, std::io::Error>`, потому что файла может не быть, прав на чтение может не хватать, путь может быть некорректным и так далее.

### Что нужно сделать

Подключи:

```rust
use std::fs::File;
```

Напиши функцию:

```rust
fn open_file_with_message(path: &str)
```

Она должна:

- вызвать `File::open(path)`;
- через `match` обработать `Ok` и `Err`;
- при успехе вывести, что файл открыт;
- при ошибке вывести путь и текст ошибки.

Проверь на существующем файле `Cargo.toml` и на несуществующем файле `missing.txt`.

## Задание 5. Создать файл, если его нет

### Краткая теория

Ошибки одного типа могут иметь разные причины. У `std::io::Error` есть метод `kind`, который возвращает `ErrorKind`. Это позволяет отдельно обработать, например, ситуацию `ErrorKind::NotFound`, а остальные ошибки оставить как настоящие сбои.

### Что нужно сделать

Подключи:

```rust
use std::fs::File;
use std::io::ErrorKind;
```

Напиши функцию:

```rust
fn open_or_create(path: &str) -> File
```

Логика:

- попробуй открыть файл через `File::open`;
- если файл открылся, верни `File`;
- если ошибка имеет `ErrorKind::NotFound`, создай файл через `File::create`;
- если файл создать не удалось, вызови `panic!` с сообщением;
- если ошибка открытия была не `NotFound`, тоже вызови `panic!`.

Проверь функцию на файле `chapter_9_note.txt`. После запуска файл должен появиться в корне проекта.

## Задание 6. unwrap и expect

### Краткая теория

Методы `unwrap` и `expect` извлекают значение из `Ok`, но вызывают `panic!`, если внутри `Err`. `expect` обычно предпочтительнее `unwrap`, потому что позволяет написать собственное сообщение и быстрее понять причину сбоя.

### Что нужно сделать

Напиши два маленьких примера:

1. Открой `Cargo.toml` через `File::open("Cargo.toml").unwrap()`.
2. Открой `Cargo.toml` через `File::open("Cargo.toml").expect("Cargo.toml должен существовать в корне проекта")`.

Затем временно замени путь на `no_file.txt` и сравни сообщения паники для `unwrap` и `expect`.

В конце оставь рабочую версию кода, которая не паникует при `cargo run`.

## Задание 7. Проброс ошибки через match

### Краткая теория

Функция может не обрабатывать ошибку сама, а вернуть её вызывающему коду. Для этого возвращают `Result<T, E>`. Внутри можно использовать `match`: при `Ok` продолжить работу, при `Err(e)` вернуть `Err(e)` из функции.

### Что нужно сделать

Подключи:

```rust
use std::fs::File;
use std::io::{self, Read};
```

Напиши функцию без оператора `?`:

```rust
fn read_file_manual(path: &str) -> Result<String, io::Error>
```

Она должна:

- открыть файл через `File::open`;
- если открыть не удалось, вернуть `Err(error)`;
- создать пустую `String`;
- прочитать файл через `read_to_string`;
- если чтение не удалось, вернуть `Err(error)`;
- при успехе вернуть `Ok(contents)`.

Проверь на `Cargo.toml` и `missing.txt`, обработав результат в `main` через `match`.

## Задание 8. Проброс ошибки через оператор ?

### Краткая теория

Оператор `?` сокращает типичный `match` для `Result`: если значение `Ok`, он достает внутреннее значение; если `Err`, он сразу возвращает ошибку из текущей функции. Использовать `?` можно только в функции, которая возвращает совместимый тип, например `Result`.

### Что нужно сделать

Перепиши функцию из предыдущего задания:

```rust
fn read_file_short(path: &str) -> Result<String, std::io::Error>
```

Требования:

- используй `File::open(path)?`;
- используй `read_to_string(&mut contents)?`;
- верни `Ok(contents)`;
- сравни поведение с `read_file_manual`.

Дополнительно: напиши ещё более короткую функцию:

```rust
fn read_file_builtin(path: &str) -> Result<String, std::io::Error>
```

Внутри используй `std::fs::read_to_string(path)`.

## Задание 9. main возвращает Result

### Краткая теория

Оператор `?` нельзя использовать в обычной `fn main()`, которая возвращает `()`, если ошибка должна быть проброшена наружу. Но `main` может возвращать `Result<(), E>`. Тогда `?` можно использовать прямо в `main`, а при ошибке программа завершится и выведет её.

### Что нужно сделать

Временно измени сигнатуру `main`:

```rust
fn main() -> Result<(), Box<dyn std::error::Error>>
```

Внутри `main`:

- прочитай `Cargo.toml` через `std::fs::read_to_string("Cargo.toml")?`;
- выведи первые 80 символов или первые несколько строк;
- верни `Ok(())`.

Затем попробуй путь `missing.txt` и посмотри, как программа сообщает об ошибке. После эксперимента верни путь `Cargo.toml`, чтобы `cargo run` снова завершался успешно.

## Задание 10. Option и оператор ?

### Краткая теория

Оператор `?` работает не только с `Result`, но и с `Option`. В функции, которая возвращает `Option<T>`, выражение `some_option?` достает значение из `Some`, а при `None` сразу возвращает `None`. `Result` и `Option` нельзя смешивать автоматически: функция должна возвращать подходящий тип.

### Что нужно сделать

Напиши функцию:

```rust
fn first_char_of_first_word(text: &str) -> Option<char>
```

Она должна:

- получить первое слово через `text.split_whitespace().next()?`;
- получить первый символ этого слова через `word.chars().next()?`;
- вернуть `Some(char)`.

Проверь функцию на строках:

- `"Rust handles errors"`;
- `"   привет мир"`;
- `""`;
- `"   "`.

Выведи результат через `match`.

## Задание 11. Валидация пользовательского ввода

### Краткая теория

Если ошибка ожидаема и пользователь может её исправить, обычно лучше вернуть `Result`, а не вызывать `panic!`. Так вызывающий код сможет показать сообщение, попросить ввести данные снова или выбрать запасной сценарий.

### Что нужно сделать

Напиши функцию:

```rust
fn validate_username(username: &str) -> Result<(), String>
```

Правила:

- имя не должно быть пустым после `trim`;
- длина имени должна быть не меньше 3 символов;
- имя должно состоять только из ASCII-букв, цифр или символа `_`;
- при ошибке возвращай `Err` с понятным текстом;
- при успехе возвращай `Ok(())`.

Проверь значения:

- `"alice"`;
- `"bo"`;
- `""`;
- `"bad name"`;
- `"user_123"`.

Для каждого значения выведи, принято оно или отклонено, и почему.

## Задание 12. Итоговая задача: загрузка настроек

### Краткая теория

В реальном коде `Result` часто проходит через несколько функций: одна читает файл, другая разбирает содержимое, третья принимает решение, что делать с ошибкой. Оператор `?` помогает оставить код линейным, но ошибки всё равно явно видны в типе возвращаемого значения.

### Что нужно сделать

Создай файл `settings.txt` в корне проекта со строками:

```text
host=localhost
port=8080
debug=true
```

Опиши структуру:

```rust
struct Settings {
    host: String,
    port: u16,
    debug: bool,
}
```

Напиши функции:

```rust
fn load_settings(path: &str) -> Result<Settings, String>
fn parse_settings(text: &str) -> Result<Settings, String>
```

Требования к `load_settings`:

- прочитать файл через `std::fs::read_to_string(path)`;
- ошибку чтения преобразовать в `String` с понятным сообщением;
- передать текст в `parse_settings`;
- вернуть результат.

Требования к `parse_settings`:

- найти строки `host=...`, `port=...`, `debug=...`;
- если какого-то ключа нет, вернуть `Err`;
- `port` разобрать как `u16`, ошибку преобразовать в понятный `String`;
- `debug` разобрать как `bool`, допустимы только `true` и `false`;
- при успехе вернуть `Ok(Settings { ... })`.

Проверь:

- корректный файл;
- отсутствующий файл;
- файл без `port`;
- файл с `port=abc`;
- файл с `debug=yes`.

Ограничение: используй только стандартную библиотеку и материал из глав 1-9. Не используй внешние crate.
